# Work items

## Create or edit an issue

- Press `C` to open **Create issue**. Choose **Type**, enter a **Title** and **Description**, and use **Project** and **Location** to place the work. Fill any required team fields before submitting. Use **Create more** when entering several items in succession.
- Open an issue from Board or Backlog. Use the detail view to edit its title or description, change **State**, pick an **Assignee**, or change **Labels**. Use **Add comment** for discussion. Use **Work context** to see the contract, runs, evidence, and decision history when you need the delivery record.
- To change priority from Board, focus an issue or select several and press `P` to open **Set priority**. Use **Urgent**, **High**, **Medium**, or **Low** to convey relative urgency; **No priority** is distinct from Low.

**State** is the team's workflow position. **Commitment** says whether a proposal has been taken on. A candidate proposed to start in Ready does not become committed by virtue of that proposed state. The exact states may differ by team.

**Type** in the creation form offers work kinds such as Issue, Epic, or Decision, and can launch the bug report flow. This is different from a Type label (Bug, Feature, Improvement, Research, or Incident). An item can have only one Type label; choosing another replaces that Type. Use other labels for categorization.

## Peek, link, and split work

- On Board, focus an issue and press `Space` to peek. Use **Open** or `Enter` for the detail drawer. Where you can edit, adjust **Status** or **Assignee** in the peek, or click **Edit description** and then **Save**. If the server copy changed, compare **Server** with **Your draft** before choosing **Apply my draft** or **Discard my draft**.
- In **Relations**, choose **Add relation**, pick a **Relation type**, enter the other issue's identifier, and click **Add**. Use **Blocking** when this issue must finish first and **Blocked by** when the other issue must finish first. Use **Related to** for context without implying a dependency.
- To split an issue, use **Add sub-issue** in **Sub-issues**. The parent is preselected. This records ownership of the smaller task under the parent; it does not by itself add a blocking link.
